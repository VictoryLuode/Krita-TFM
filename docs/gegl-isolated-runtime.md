# GEGL isolated operation runtime

TFM discovers GIMP through its current installation (or an explicit TFM runtime prefix) and resolves directory links to the concrete version before loading it. No user environment configuration is required. GIMP itself is never modified.

The production bridge generates `<ResourceDirectory>/TFM/gegl/modules-v1/<content-id>/` on first use. It copies only core, common, common-gpl3, common-cxx, generated and transform operation families, including available CPU variants. Required base modules are checked. The identity includes SHA-256 hashes of those modules, all GIMP bin DLLs and babl modules. A GIMP update therefore selects a new generation. Existing generations are retained. Corrupt generations fail closed and are preserved for inspection; repair must happen with the host closed.

Preparation uses a process lock, verifies each copy, writes a manifest and publishes the complete directory through a same-volume rename. Each startup verifies the manifest, exact DLL set and copied DLL hashes. Unrelated image/file codec modules are never scanned. Full GIMP module initialization previously timed out, and several file codec modules reproduced that behavior independently.

Windows core libraries are loaded by absolute paths. Curated modules are preloaded with explicit dependency search flags because later GModule lazy loads otherwise fail when GIMP is absent from PATH. A temporary AddDllDirectory cookie is removed after initialization; PATH and default DLL search policy are not changed. GEGL_PATH and BABL_PATH are set only around initialization, then removed.

GEGL registration is process-global. TFM serializes its own callers, rejects any preexisting GEGL DLL and rejects external GEGL_PATH/BABL_PATH instead of silently adopting or replacing them. Concurrent initialization by unrelated plugins is unsupported: GEGL provides no inter-plugin ownership protocol. The initialized runtime and module references remain loaded until process exit. Do not call gegl_exit from TFM.

Build output is linked to a candidate DLL, with prior output saved under a content-addressed rollback directory before atomic replacement. The local deploy script similarly stages and verifies native artifact copies, preserves rollback bytes and leaves unknown Python files intact. No installation is required to generate a private runtime during an isolated test. The deployment command still requires Krita to be closed.

These module copies are generated from the user's local GIMP installation for local use. This implementation does not establish permission or fulfill obligations for redistributing GIMP DLLs; a release bundling them requires a separate license/source compliance review.

For provenance, upstream GEGL 0.4.72 marks [focus-blur.c](https://raw.githubusercontent.com/GNOME/gegl/GEGL_0_4_72/operations/common-cxx/focus-blur.c) and [lens-blur.cc](https://raw.githubusercontent.com/GNOME/gegl/GEGL_0_4_72/operations/common-cxx/lens-blur.cc) LGPL-3.0-or-later; [motion-blur-circular.c](https://raw.githubusercontent.com/GNOME/gegl/GEGL_0_4_72/operations/common-gpl3%2B/motion-blur-circular.c) and [motion-blur-zoom.c](https://raw.githubusercontent.com/GNOME/gegl/GEGL_0_4_72/operations/common-gpl3%2B/motion-blur-zoom.c) are GPL-3.0-or-later. [GIMP 3.2.6 release notes](https://www.gimp.org/news/2026/09/10/gimp-3-2-6-released/) identify GEGL 0.4.72 and babl 0.1.128 in that release; these references alone do not establish the precise provenance or license inventory of an individual installed binary. TFM's motion renderer uses its own fixed-sample implementation and Focus uses a modified processing graph; upstream operation names are not proof that the implementation is identical.

Before any bundled redistribution, identify the exact DLL versions, their corresponding source and build modifications, transitive dependencies, copyright notices and applicable licenses; prepare the required notices, license texts and corresponding-source or replacement arrangements for the distribution method. Assess TFM's own code provenance and licensing separately. This is an outstanding release review, not a conclusion that a particular bundle is compliant.

Offline validation uses the unchanged native KisFilter regression harness linked against production objects, with no GEGL_PATH, BABL_PATH, TFM_GEGL_PREFIX or test prelicense. Use a private kritarc ResourceDirectory, configuration directories and an existing empty KRITA_PLUGIN_PATH. The installed Krita runtime uses its bin directory as QT_PLUGIN_PATH (platforms is inside bin). A successful standalone regression alone does not establish live host filter-layer scheduling or UI behavior.
